# 输入提取与卡片解析

## 支持输入

- TXT / Markdown：直接读取。保留标题、段落和列表结构。
- DOCX：使用 `python-docx` 读取段落和表格。表格优先按行解析。
- PPTX：使用 `python-pptx` 逐页读取标题、文本框和表格。一页中的标题与正文可作为一个上下文组。
- PDF：优先使用 `pdfplumber`；若页面主要是扫描图片，则按图片处理。
- PNG / JPG / JPEG / WEBP：使用可用的图像查看能力读取文字。不得凭模糊图像补造内容。
- 粘贴文本：直接进入解析阶段。

依赖缺失时安装：

```powershell
pip install python-docx python-pptx pdfplumber
```

## 输入组合

用户可以提供多个文件。按文件顺序合并内容，并保留来源边界：

```json
{
  "source": "chapter1.pdf",
  "section": "第一章"
}
```

来源边界只在需要分类或词汇表分组时写入 `section`。不要为了内部处理向卡片正文添加来源标签。

## 模式判断

### 英译汉

满足任一条件时优先判断为英译汉：

- 大量条目为英文术语配中文翻译。
- 明确出现双语列、双语表头或 `English: 中文` 结构。
- 英文和中文成对出现且中文明显是译义。

section 默认使用 `en-cn`。

### 名词解释

满足任一条件时优先判断为名词解释：

- 中文术语后接定义、机制、特征或应用说明。
- 条目使用 `术语：定义`、`术语——定义` 或“所谓……是指……”等结构。
- 术语较短，背面明显是解释性文本。

section 默认使用 `cn-def`。

### 混合

同一批材料中同时存在稳定的双语和定义条目时使用混合模式。按来源章节、标题或用户提供的话题分组，不要按单张卡片随意切换。

### 指定模式

用户指定 `--mode` 时以用户指定为准。材料不适合该模式时应说明问题，而不是强行拆分。

## 卡片对解析

按以下优先级尝试：

1. 表格的两列。忽略序号列和空列。
2. 明确分隔符：`→`、`←`、`:`、`：`、`-`、`—`、`\t`、`|`。
3. 编号列表或项目符号中的成对内容。
4. 术语段落与紧随其后的定义段落。
5. 标题后接正文的教材结构。
6. 自然段落中的“术语 + 定义”句式。

解析时：

- 去掉无意义前缀，如“定义：”“解释：”“翻译：”。
- 保留术语大小写、上下标含义和专业缩写。
- 不截断定义中的关键条件、限制或公式说明。
- 同一术语有多个义项时，保留为独立卡片，并在 `front` 中保留限定语。
- 纯标题、页码、目录项和明显噪声不生成卡片。
- 无法确定配对关系时，把原文作为候选记录并标记 `[待核对]`，不要猜。

## 去重与规范化

去重键为：

```text
normalize(front) + "\u0000" + normalize(back)
```

规范化只处理首尾空白、连续空白和大小写比较，不改变最终展示文本。相同 key 保留第一次出现的版本。

## 最低质量检查

生成前检查：

- `front` 和 `back` 均非空。
- 卡片数量大于 0。
- 多数卡片具有可理解的定义或翻译关系。
- 没有把整段教材正文原样塞进单张卡片。
- 不确定内容已标记。

卡片少于 3 张时继续生成，但在最终回复中提醒用户。
